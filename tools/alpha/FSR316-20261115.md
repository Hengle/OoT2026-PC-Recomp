# AMD FSR 3.1.6 — private test, 2026-11-15

Adds an explicit **AMD FSR 3.1.6** upscaler in launcher Settings → Quality and the F1 graphics menu. Public launcher version remains 1.0.9; this change has not been released publicly.

## Implementation

- Saved option `dlss=7` is appended. Existing values 0–6 retain their meaning. The older source-built FSR 3.1 option stays available.
- Uses the analytical **3.1.6** provider in the already distributed AMD FidelityFX SDK **2.4.0** Vulkan runtime. Provider enumeration selects this exact version and verifies the created context reports it. No automatic substitution with 4.x or an older 3.x provider.
- FSR 3.1.6 uses linear scene colour, automatic exposure, existing depth/motion/jitter inputs and history reset handling. Linear input/output processing works with SDR without enabling display HDR. The FSR 4 shader tuning hooks are bypassed for 3.1.6.
- Separate contexts, temporal histories and failure state for runtime 3.1.6, FSR 4, legacy FSR 3.1 and DLSS. GPU context destruction is deferred as before.
- Missing runtime/provider leaves the saved choice intact and falls back to the game's own upscale. F1 reports the actual fallback; legacy FSR remains available.
- AMD API validation exposed a missing API-version descriptor and missing explicit unit exposure for SDR FSR 4 on Windows. Both are supplied now. The final switch test confirms FSR 4 dispatches successfully rather than silently falling back.
- `OCR_FSR_API_DEBUG=1` enables AMD validation messages. `RX_VK_FSR316=0` disables only the new runtime 3.1.6 option.
- `engine_fsr316.py` applies checked, repeatable staging replacements after engine rebranding. The private installer also updates installed engine sources, so rebuilding retains this option.

## Validation

- Four regression tests: fresh/repeated staging, launcher settings round trip, native menu/resolution/LOD navigation, and compiled production context functions with provider/API descriptor validation, separate state and deferred release.
- Windows Vulkan renderer compiled successfully. No game EXE or shader-translator changes. All 250 translator inputs are identical to baseline; shader ABI stamp remains `1cd445ea9d3fb649`.
- Isolated game tests use copied saves and the documented control bridge. RX 7900 XTX, 2560×1440 output, 67% Quality, existing frame interpolation 2×. The log confirms actual 3.1.6 provider creation and dispatch.
- Initial warmed market sample: 1,140 frames, 59.97 base FPS, worst frame 43.281 ms; no frames over 50 ms in that short sample. GPU time averaged 5.65 ms. These are limited local observations, not proof of an improvement on other PCs or long exploration sessions.
- Final API-validation run switches 3.1.6 native → FSR 4 → legacy FSR 3.1 → 3.1.6 Quality. Each renderer dispatches; no AMD validation errors or dispatch failures. Native and FSR 4 screenshots were inspected.
- Runtime test without the AMD DLLs: saved value 7 remains, F1 reports "Game's own", the market renders, and legacy FSR 3.1 still works.
- Private installer fixture: all 21 payload hashes and original backups verified. Invalid game/launcher and incompatible EXE are rejected. Repeated installation is rejected. Restore reproduces the originals, refuses unrelated later versions, and leaves saves/settings/voices/caches intact. The live installation was untouched by these fixture tests.

## Limits and testing guidance

This updates **upscaling**, not the version of frame generation. Existing frame interpolation remains independently selectable. First context creation can pause while its own pipelines are prepared (about 498 ms cold in the initial local run, around 50 ms warm); no full shader-cache invalidation is required.

There is no universal RAM/VRAM or FPS improvement claim. The 3.1.6 context reported 217 MiB at 1440p versus 181 MiB for FSR 4. Total process memory remains affected by the game's asset cache and other renderer resources. NVIDIA/Intel hardware and Linux were not physically tested.

Suggested first comparison: **FSR 3.1.6 + 67% Quality**, keep other settings unchanged, compare the same route with the previous upscaler. 100% is available for native-resolution antialiasing.
